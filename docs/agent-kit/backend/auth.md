# Authentication and Authorization (Better Auth)

> **Read when:** identity/private access exists or the task proposes it.
> **Scope:** preferred Better Auth session recipe when selected. Preserve an approved existing provider. Authorization requirements apply to all private operations; public content does not need auth infrastructure.

## Pieces

| Path | Purpose |
|---|---|
| `src/server/auth/auth.ts` | `export const auth = betterAuth({...})`: providers, plugins, Drizzle adapter, rate limit |
| `src/server/auth/session.ts` | `getCurrentUser()` (cached per request), `requireActor()` (throws), `requireUser()` (page redirect) |
| `src/lib/auth-client.ts` | `createAuthClient()` for Client Components (sign-in/out, session hooks) |
| `src/app/api/auth/[...all]/route.ts` | `export const { GET, POST } = toNextJsHandler(auth)` |
| `src/server/db/schema/auth.ts` | Tables generated by Better Auth's CLI (users, sessions, accounts, verifications) |
| `src/proxy.ts` | Optimistic redirect when no session cookie exists (UX only) |

## Session helpers (created at bootstrap)

```ts
// src/server/auth/session.ts
import "server-only";
import { headers } from "next/headers";
import { redirect } from "next/navigation";
import { cache } from "react";

import { AppError } from "@/lib/errors";

import { auth } from "./auth";

export type SessionUser = typeof auth.$Infer.Session.user;

/** The signed-in user, or null. Deduplicated per request. Dynamic: call it inside <Suspense>. */
export const getCurrentUser = cache(async (): Promise<SessionUser | null> => {
  const session = await auth.api.getSession({ headers: await headers() });
  return session?.user ?? null;
});

/** Data-layer boundary: no redirect or browser-controlled actor IDs. */
export async function requireActor(): Promise<SessionUser> {
  const user = await getCurrentUser();
  if (!user) throw new AppError("unauthenticated");
  return user;
}

/** Page-only UX: call inside the dynamic region, not in API/business code. */
export async function requireUser(): Promise<SessionUser> {
  const user = await getCurrentUser();
  if (!user) redirect("/sign-in");
  return user;
}
```

> The helper above is monolingual. When i18n is selected, replace only page navigation with the chosen locale-aware adapter and resolve locale there. Business/data helpers remain transport-independent. For API keys, webhooks, or jobs, define and verify the appropriate server principal rather than accepting an arbitrary ID or fabricating a session.

## Rules: authentication

- **AUTH-1 (MUST)** The **data layer** is the security boundary. Every exported private query/mutation resolves and authorizes a verified actor itself (session references use `requireActor()`). Page UX may call `requireUser()` first; data functions throw safe errors rather than redirect. Existing service-principal architectures must document their trusted boundary. Layouts, `proxy.ts` and hidden buttons are UX, never security. (Layouts don't re-run on client navigation, and proxy checks have been bypassed before.)
- **AUTH-2 (MUST)** `proxy.ts` only checks whether the session cookie *exists* (`getSessionCookie`), to redirect early. It never validates sessions or permissions.
- **AUTH-3 (MUST)** Sessions are httpOnly, Secure, SameSite=Lax cookies managed by Better Auth. Never store tokens in `localStorage`, and never expose them to client JavaScript.
- **AUTH-4 (MUST)** Email/password accounts require email verification before accessing the app (when email sending is configured). Passwords have a minimum of 8 characters and maximum length limits enforced by Better Auth. Don't add composition rules, and allow paste.
- **AUTH-5 (MUST)** Keep Better Auth's built-in rate limiting on, with storage that works on serverless (`"database"`, or secondary storage such as Redis), not in-memory.
- **AUTH-6 (MUST)** `BETTER_AUTH_SECRET` is ≥ 32 random bytes and differs per environment. `BETTER_AUTH_URL` matches the deployed origin. Trusted origins are explicit.
- **AUTH-7 (MUST)** After sign-in, redirect only to **relative, same-site** paths (validate `callbackUrl`/`next` to start with `/` and not `//`), to prevent open redirects.
- **AUTH-8 (MUST)** Auth pages (`(auth)` group) are `noindex`, use `autocomplete` attributes, and give generic errors ("Invalid email or password"). They never reveal whether an account exists.
- **AUTH-9 (SHOULD)** Offer at least one social provider and/or passkeys, through Better Auth plugins, to reduce password risk. Add 2FA (plugin) before handling sensitive data.

## Rules: authorization

- **AUTH-20 (MUST)** Deny by default. Every private read or write states its rule explicitly in the data layer, e.g. "owner can edit", "org admin can invite".
- **AUTH-21 (MUST)** Check ownership/membership **in the query** (`WHERE owner_id = $user`), not by loading first and comparing in JS when avoidable.
- **AUTH-22 (MUST)** Return **404** (`AppError("notFound")`), not 403, when a user asks for a resource they can't see, so existence isn't leaked. Use 403 when the user can see the resource but not perform the action.
- **AUTH-23 (MUST)** Keep permission logic in pure, tested functions per feature (`canEditProject(user, project)`) when it is more than a single ownership check.
- **AUTH-24 (MUST)** Roles and permissions come from the DB/session on the server, never from client input, URL params, or JWT claims you didn't issue.
- **AUTH-25 (SHOULD)** For teams/multi-tenancy, use Better Auth's organization plugin (members, roles, invitations) and scope every tenant query by `organizationId` (DB-10). Changing the permission model needs an ADR.

## Protecting pages

```tsx
// src/app/[locale]/(app)/layout.tsx: UX convenience plus the app shell.
// Private queries still enforce requireActor() themselves (AUTH-1).
export default function AppLayout({ children }: LayoutProps<"/[locale]">) {
  return (
    <AppShell>
      <Suspense fallback={<AppShellSkeleton />}>{children}</Suspense>
    </AppShell>
  );
}
```

Set `robots: { index: false }` in the metadata of the `(app)` and `(auth)` layouts.

## Account lifecycle (privacy requirements)

- Users can change their email (with verification) and password, revoke sessions, export their data, and delete their account. Deletion cascades or anonymizes their data; see [analytics-and-privacy.md](../discoverability/analytics-and-privacy.md).
- Log security events (sign-in, failed sign-in bursts, password change, role change, account deletion) to the audit log, without passwords or tokens.
