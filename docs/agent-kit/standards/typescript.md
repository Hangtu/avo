# TypeScript

> **Read when:** writing any `.ts`/`.tsx` code or changing `tsconfig.json`.
> **Enforced by:** `tsc --noEmit` (`pnpm typecheck`), typescript-eslint (type-aware rules), code review.

## Compiler settings (non-negotiable)

`tsconfig.json` keeps the create-next-app base and adds these strict flags. Loosening any of them requires an ADR.

```jsonc
{
  "compilerOptions": {
    "strict": true,
    "noUncheckedIndexedAccess": true,   // arr[i] and record[key] may be undefined
    "noImplicitOverride": true,
    "noFallthroughCasesInSwitch": true,
    "noUnusedLocals": true,
    "noUnusedParameters": true,
    "verbatimModuleSyntax": true,       // forces `import type`
    "allowJs": false,
    "paths": { "@/*": ["./src/*"] }     // no baseUrl (deprecated in TS 6)
  }
}
```

## Rules

- **TS-1 (MUST NOT)** Use `any`, including implicitly. Use `unknown` and narrow it, or write the real type.
- **TS-2 (MUST NOT)** Use `@ts-ignore` or `@ts-nocheck`. `@ts-expect-error -- <reason>` is allowed only in tests that check invalid input.
- **TS-3 (MUST NOT)** Use the non-null assertion `!`, except right after a check the compiler can't follow, with a comment. Prefer narrowing or throwing.
- **TS-4 (MUST NOT)** Use type assertions (`as Foo`) to silence errors. Allowed uses: `as const`; narrowing DOM types that are proven safe; test fixtures. Never `as unknown as T`.
- **TS-5 (MUST)** Use `type` aliases by default. Use `interface` only for declaration merging (module augmentation).
- **TS-6 (MUST)** Use string-literal unions plus `as const` arrays instead of `enum` or `namespace`.
- **TS-7 (MUST)** Model variants as **discriminated unions** and handle them with exhaustive `switch` (lint: `switch-exhaustiveness-check`):

  ```ts
  type ActionResult<T> = { ok: true; data: T } | { ok: false; code: ErrorCode };

  function assertNever(value: never): never {
    throw new Error(`Unhandled value: ${String(value)}`);
  }
  ```

- **TS-8 (MUST)** Validate data that crosses a trust boundary at runtime with Zod: user input, `searchParams`, env vars, webhook bodies, third-party responses, `JSON.parse` output, `localStorage`. Derive the static type from the schema (`z.infer`); never declare it twice.
- **TS-9 (MUST)** Derive types instead of duplicating them:
  - DB rows: `typeof projects.$inferSelect` / `$inferInsert`
  - schemas: `z.infer<typeof schema>`
  - props: `React.ComponentProps<typeof Button>`
  - routes: `PageProps<"/[locale]/projects/[projectId]">`, `LayoutProps<…>`, `RouteContext<…>` (generated by Next.js, global, no import)
  - utility types: `Pick`, `Omit`, `Partial`, `Awaited<ReturnType<typeof fn>>`
- **TS-10 (MUST)** Exported functions in `lib/` and `server/` declare explicit return types. Inference is fine for local functions and components.
- **TS-11 (MUST)** Use `readonly` and `as const` for data that must not change (config, constant lists). Use `satisfies` to check a shape without widening it.
- **TS-12 (SHOULD)** Prefer `Record<K, V>` with a literal-union `K` over index signatures. Use `Map` for dynamic keys.
- **TS-13 (MUST)** Await `params` and `searchParams` in pages, layouts and route handlers. They are Promises.
- **TS-14 (MUST NOT)** Use `Function`, `Object`, `{}`, or `object` as types. Write the actual signature or shape.
- **TS-15 (SHOULD)** Use branded types for IDs only where mixing IDs has caused bugs. Don't brand by default.

## Type-aware lint rules in use

`no-floating-promises`, `no-misused-promises`, `await-thenable`, `switch-exhaustiveness-check`, `consistent-type-imports`, `no-unnecessary-condition`, `prefer-nullish-coalescing`, `no-explicit-any`, `ban-ts-comment`, `naming-convention`.

## Versions

TypeScript is pinned to `~6.0` because typescript-eslint doesn't yet support TypeScript 7. When it does, upgrade following [upgrade-dependencies.md](../playbooks/upgrade-dependencies.md), and record the change in [tech-stack.md](../architecture/tech-stack.md).
