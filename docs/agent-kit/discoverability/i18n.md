# Internationalization (next-intl)

> **Read when:** i18n is active and the task changes text, formatting, navigation, or locales.
> **Scope:** next-intl recipe for selected multi-language apps. A monolingual app needs no catalogs, locale segment, provider, middleware, or message check. Preserve an approved existing localization implementation.
> **Decision:** [ADR 0006](../architecture/decisions/0006-next-intl-routing.md). URLs: default locale unprefixed (`/pricing`), others prefixed (`/es/pricing`).

## Files

| File | Purpose |
|---|---|
| `messages/<locale>.json` | Message catalogs. The **default locale is the source of truth** for keys |
| `src/i18n/routing.ts` | `defineRouting({ locales, defaultLocale, localePrefix: "as-needed" })` |
| `src/i18n/navigation.ts` | `createNavigation(routing)`: exports `Link`, `redirect`, `useRouter`, `usePathname`, `getPathname` |
| `src/i18n/request.ts` | `getRequestConfig`: resolves the locale (root param, or explicit) and loads messages |
| `src/proxy.ts` | `createMiddleware(routing)` from `next-intl/middleware` (locale detection, redirects, rewrites) |
| `src/types/next-intl.d.ts` | `AppConfig` augmentation: typed `Locale` and message keys |
| `scripts/check-messages.ts` | `pnpm i18n:check`: every locale has exactly the keys of the default locale |

## Core setup (created at bootstrap; verify against the next-intl docs for the installed version)

```ts
// src/i18n/routing.ts
import { defineRouting } from "next-intl/routing";

export const routing = defineRouting({
  locales: ["en", "es"],
  defaultLocale: "en",
  localePrefix: "as-needed",
});
```

```ts
// src/i18n/request.ts
import * as rootParams from "next/root-params";
import { hasLocale } from "next-intl";
import { getRequestConfig } from "next-intl/server";

import { routing } from "./routing";

export default getRequestConfig(async ({ locale }) => {
  // `locale` is set when a caller passes it explicitly (Route Handlers, Server Actions, metadata routes).
  // Pages and layouts read it from the [locale] root param, which works with Cache Components.
  const candidate = locale ?? (await rootParams.locale());
  const resolved = hasLocale(routing.locales, candidate) ? candidate : routing.defaultLocale;
  return {
    locale: resolved,
    messages: (await import(`../../messages/${resolved}.json`)).default,
  };
});
```

```tsx
// src/app/[locale]/layout.tsx (root layout)
export function generateStaticParams() {
  return routing.locales.map((locale) => ({ locale }));
}

export default async function LocaleLayout({ children, params }: LayoutProps<"/[locale]">) {
  const { locale } = await params;
  if (!hasLocale(routing.locales, locale)) notFound();

  return (
    <html lang={locale} dir={getLocaleDirection(locale)} suppressHydrationWarning>
      <body className={fontVariables}>
        <NextIntlClientProvider>{/* inherits locale + messages from the server */}
          <Providers>{children}</Providers>
        </NextIntlClientProvider>
      </body>
    </html>
  );
}
```

## Rules

- **I18N-1 (MUST)** No hardcoded user-facing strings anywhere: JSX text, `aria-label`, `alt`, `title`, placeholders, metadata, emails, toasts, validation messages, error pages. Use `useTranslations` (Client/sync Server Components) or `await getTranslations` (async Server Components, metadata).
- **I18N-2 (MUST)** Add every new key to **all** locale files in the same change. If you can't translate, add the default-locale text and flag it in the PR (`pnpm i18n:check` fails on missing keys).
- **I18N-3 (MUST)** Namespaces follow features: `Projects`, `Billing`. Shared ones: `Common`, `Navigation`, `Metadata`, `Validation`, `Errors`. Keys follow [naming.md](../standards/naming.md) (NAME-50, NAME-51).
- **I18N-4 (MUST)** Use ICU syntax for variables, plurals and selects. Never concatenate translated fragments:

  ```json
  "projectCount": "{count, plural, =0 {No projects} one {# project} other {# projects}}",
  "greeting": "Welcome back, {name}!",
  "status": "{status, select, active {Active} archived {Archived} other {Unknown}}"
  ```

- **I18N-5 (MUST)** Use `t.rich` for text with inline markup (links, bold), never split sentences around elements.
- **I18N-6 (MUST)** Format dates, times, numbers, currencies, lists and relative times with next-intl (`useFormatter` / `getFormatter`), with shared formats in `src/i18n/request.ts`. Never call `toLocaleString()` without a locale, and never use manual formatting.
- **I18N-7 (MUST)** Internal navigation uses only `@/i18n/navigation` (`Link`, `redirect`, `useRouter`, `usePathname`, `getPathname`). ESLint blocks `next/link`, and navigation imports from `next/navigation`.
- **I18N-8 (MUST)** Server Actions and Route Handlers don't have the `[locale]` root param. They return **codes** (translated by the client), or call `getTranslations({ locale, namespace })` with a locale they received explicitly.
- **I18N-9 (MUST)** Layout supports RTL: `dir` on `<html>`, logical CSS properties (CSS-6), and direction-aware icons (mirror arrows/chevrons with `rtl:rotate-180`).
- **I18N-10 (MUST)** Store times in UTC; display them in the user's time zone (from profile settings, else the browser). Pass `timeZone` to the formatter explicitly to avoid server/client mismatches.
- **I18N-11 (MUST)** Each locale has its own metadata (title, description, OG) and is listed in hreflang alternates and the sitemap (see [seo.md](seo.md)).
- **I18N-12 (SHOULD)** Allow ~40% extra width for translated text. Never fix widths to fit English.
- **I18N-13 (MUST)** The locale switcher shows each language in its own language (`English`, `Español`), with `lang` set on each option, and keeps the current path.
